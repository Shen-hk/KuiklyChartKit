# 竞争性交付方案

## 定位

目标不是“能画出几种图”，而是一个评审可以立即运行、操作、验证并愿意在真实项目中接入的 Kuikly 图表库。核心卖点是：**官方风格 DSL、跨端一致的基础交互、密集数据不失真、完整证据链**。

公开对标已展示图表数量、主题和点击 Tooltip。我们的可见差异是模块化内核、可靠的选择交互、分组/堆叠/组合图、错误数据处理、性能实验室、测试与正式平台录屏。不要复用对标仓库的代码、名称、截图或设计资产。

## 功能优先级与最终效果

| 优先级 | 功能 | 怎么实现 | 用户能看到的效果 |
| --- | --- | --- | --- |
| P0 | 折线图 | `CartesianLayout` + `LineRenderer` + Canvas 路径；直线/平滑切换。 | 带轴、漂亮刻度、网格、点、图例和点击 Tooltip 的趋势图。 |
| P0 | 柱状图 | 共用坐标/轴；每根柱生成命中包围盒。 | 自定义色、圆角、标签、零基线和负值柱。 |
| P0 | 官方式 DSL | `ViewContainer` 扩展 + `ComposeView<Attr, Event>`。 | 使用者只写 `LineChart { attr { ... } event { ... } }`。 |
| P0 | 主题/格式化 | `ChartTheme`、`AxisFormatter`、`ValueFormatter`，明确优先级。 | Light/Dark/Ocean/Sunset 和正确的货币、百分比、日期。 |
| P0 | 健壮性 | 纯 Kotlin 数据域/刻度/布局；坏数据过滤、空态与单点保护。 | 空数据、重复值、长中文标签、正负值均不崩溃。 |
| P1 | 追踪与平移 | 由 RenderPlan 反查 X 槽和可视范围；已完成 Showcase 手动验收，保持默认关闭。 | 可选的探索式浏览，回调保留原始索引。 |
| P1 | 扩展图表 | 面积图、饼环图、组合图和 Sparkline 均已实现。 | 可支持仪表盘、占比和紧凑趋势。 |
| P1 | 高质量 Demo | `commonMain` Showcase、Performance Lab 与异常数据回归已实现。 | 演示可见主题、交互、100/1,000/5,000 点采样和坏点断线。 |
| P2 | 导出图片 | 已封装一次性 `DATA_URI` 异步回调；仍需升级/验证 `toImage`、三端回归与内存检查。 | 仅作为实验 API；未通过版本探针不对外宣称。 |
| P2 | 热力图/雷达图 | P2-1 已复用 Theme、Tooltip、Event 协议并加入专用矩阵/极坐标布局。 | Showcase 额外展示，绝不挤占 P0/P1 质量时间。 |

## 演示视觉规范

Showcase 采用数据洞察面板而非组件测试页：浅灰/深蓝灰背景，12f 圆角卡片，左侧标题、右侧筛选。浅色主题使用白卡、低对比网格和高饱和系列色；暗色主题保留相同空间层级与颜色语义，而不是简单反色。

`Data Explorer` 是主视觉：顶部时间范围筛选，中央为 264f 高多系列平滑折线；点击显示选中圆点和 Tooltip。数据超出可视容量时显示细微浏览提示；平移仅在显式开启且数据超出窗口时生效。

`Comparison Lab` 展示分组/堆叠切换和正负值，零轴比普通网格更醒目；柱顶值避开边界，选中柱使用半透明底板与描边。`Performance Lab` 显示输入点数、实际绘制点数、采样状态和原始索引回调；CPU 采样耗时由自动化测试记录，设备首帧与帧率由正式平台录屏补证。

## 实现顺序与质量门槛

```text
能力探针 -> P0 笛卡尔内核 -> P0 三端验收 -> 候选交互/扩展图 -> Showcase 与性能证据 -> P2
```

1. 在当前依赖中完成 Canvas、点击、文本测量、批量绘制与候选手势的最小页面，并记录结论。
2. 先完成模型、校验、坐标/刻度、文本测量、RenderPlan 与命中测试，再实现 Line/Bar；每步写 `commonTest`。
3. Android、iOS、OpenHarmony 验证空数据、单点、长标签、跨零、动态更新和点击。
4. 仅在探针通过后接入候选交互；实现 P1 图表时统一复用 Theme、Tooltip 和 Event 协议。
5. 录制 Showcase 场景、生成截图、记录性能基线、完善 README/API/KDoc，并在干净环境构建。

质量红线：不得以增加图表类型换取 P0 交互缺失、正式平台未验证、测试缺失、API 不一致或 Demo 不可运行。任一候选能力在一端不一致，应降级或隐藏，而不是宣称跨端支持。

## 评审证据包

最终 README 和 Issue 评论提供统一导航：30 秒功能总览；正式平台交互录屏；Showcase 截图与 DSL 片段；API 与接入文档；自动化测试、边界数据与 100/1,000/5,000 点记录；已知限制和 P2 路线。评审看到的不只是功能数量，而是可维护性、可复用性和真实跨端可靠性。
