# 金融行情交付方案

## 定位

目标不是堆叠图表数量，而是交付一个可在真实股票行情页面使用的 Kuikly 跨端图表组件：开发者通过官方风格 DSL 配置，用户可以可靠地看趋势、滑动查看数据、拖动缩放时间窗口，并在 K 线与成交量之间获得一致的信息。核心证明是 Android/H5 双端运行、自动化测试和 Kuikly AI 股票行情 Demo 的实际接入。

不复用第三方仓库的代码、名称、截图或设计资产。质量差异来自准确的金融数据语义、交互一致性、可恢复视口、边界测试与可复现证据。

## 里程碑与交付效果

| 阶段 | 能力 | 实现重点 | 可见结果 |
| --- | --- | --- | --- |
| M0 | 折线、柱状、DSL | `ComposeView`、数据模型、轴/刻度、RenderPlan、点击 Tooltip。 | 使用者可用声明式代码配置趋势和对比图。 |
| M1 | 十字光标、Tooltip、滑动选点 | `longPress`/拖动到统一 X 槽，Compose Tooltip 覆盖层。 | 手指/鼠标移动时可读出准确行情值。 |
| M1 | 平移与缩放 | `ChartViewport`、手势仲裁、边界钳制、能力降级。 | 可以浏览密集时间序列而不越界或抢页面滚动。 |
| M2 | K 线 + 成交量 | OHLC 校验、上下分区、共享 X 轴/视口/Tracker。 | 一张图可同时观察价格形态和成交量。 |
| M2 | 更新与边界 | 快照合并、稳定 ID、采样、回归与视觉测试。 | 新行情到达不闪烁、不选错数据，异常输入安全。 |
| M3 | Android/H5 示例与 API | 真实 H5 宿主、Showcase、KDoc、构建说明和证据。 | 双端可复现运行，而不只是静态代码。 |
| M3 | Kuikly AI 股票行情 Demo | 数据适配、真实页面接入、端到端验收。 | 组件在业务上下文中可运行、可操作。 |

## 实现顺序与质量门槛

```text
Android/H5 能力探针
  -> M0 基础图表与 DSL
  -> M1 Tracker / Pan / Zoom
  -> M2 K 线成交量、更新与边界
  -> M3 双端示例、API/KDoc
  -> Kuikly AI 股票行情 Demo 接入
```

1. 先验证当前 Kuikly 版本在 Android/H5 的 Canvas、点击、Tracker、Pan 和 Zoom 行为，记录结论与降级方案。
2. 完成纯 Kotlin 的模型、OHLC 校验、坐标、刻度、视口与命中测试，再丰富 Renderer；每项算法都进入 `commonTest`。
3. 将 Tracker、平移和缩放放在同一个交互协调器中，明确手势优先级，避免滑动选点与拖动相互抢占。
4. 在价格图稳定后实现 K 线/成交量共享时间窗口，随后处理实时数据更新、截断、异常数据和高密度采样。
5. 补齐 H5 宿主与 Android/H5 Showcase，编译所有文档示例，完成 KDoc、截图、录屏和性能记录。
6. 组件自身达到 M0–M2 门槛后，才把真实行情适配到 Kuikly AI 股票行情 Demo，并做端到端验收。

## 质量红线

- 不以增加图表类型换取 Line/Bar/DSL、Tracker、视口或 K 线金融语义的缺失。
- 不以单端可运行宣称跨端完成；Android 与 H5 缺一端证据即不能发布。
- 不以数组下标替代稳定行情身份；数据更新后不得让十字线或 Tooltip 指向另一条数据。
- 不以静态截图代替手势和动态更新验证；缩放探针失败时必须公开降级，而不是保留无效开关。
- Demo 是最终业务验证，不能掩盖组件测试、文档或 API 不一致。
